    Pong: від pong-12 до pong-final — прибирання коду¶

    1. Загальний опис завдання¶

    pong-12 — уже завершена гра, в яку можна грати. pong-final не додає нових можливостей — він прибирає код:

    • клас Ball більше не задає собі випадкову швидкість. Починаючи з pong-9, швидкість м'яча задає стан serve, тож init і reset тепер лише ставлять м'яч у центр нерухомим. Це прибирає залишки непослідовного випадкового коду з попередніх версій;
    • love.load() перевпорядковано так, щоб пов'язані речі стояли поруч, а всі змінні ініціалізуються явно (winningPlayer = 0);
    • рахунок малюється після повідомлень стану, тож м'яч і ракетки малюються поверх нього;
    • коментарі переписано так, щоб пояснити кожну функцію зворотного виклику LÖVE, а назву версії прибрано із заголовка.

    Файли¶

    Файл Що відбувається
    Ball.lua Змінюється — без випадкової швидкості в init / reset
    main.lua Змінюється — перевпорядкування й коментарі
    Paddle.lua Без змін
    sounds/*.wav Готові ресурси, без змін
    class.lua, push.lua, font.ttf Сторонні, без змін

    2. Кроки від pong-12 до pong-final¶

    Крок 1. Нехай м'яч стартує нерухомим у Ball:init¶

    У Ball.lua замініть два рядки з випадковою швидкістю в Ball:init на:

        self.dy = 0
    self.dx = 0

    Крок 2. Нехай Ball:reset зупиняє м'яч¶

    Замініть тіло Ball:reset:

    function Ball:reset()
    self.x = VIRTUAL_WIDTH / 2 - 2
    self.y = VIRTUAL_HEIGHT / 2 - 2
    self.dx = 0
    self.dy = 0
end

    Note

    М'яч отримує швидкість лише в стані serve у main.lua. Коли логіка швидкості зосереджена в одному місці, код легше зрозуміти й менше шансів на помилки.

    Крок 3. Приберіть назву версії із заголовка¶

    У main.lua видаліть ці два рядки з верхнього коментаря:

        pong-12
    "The Resize Update"

    Крок 4. Перевпорядкуйте створення об'єктів і змінних у love.load()¶

    Після push.setupScreen(...) розташуйте все в такому порядку:

        -- ракетки й м'яч
    player1 = Paddle(10, 30, 5, 20)
    player2 = Paddle(VIRTUAL_WIDTH - 10, VIRTUAL_HEIGHT - 30, 5, 20)
    ball = Ball(VIRTUAL_WIDTH / 2 - 2, VIRTUAL_HEIGHT / 2 - 2, 4, 4)

    -- рахунок
    player1Score = 0
    player2Score = 0

    -- наступним подає той, хто пропустив очко
    servingPlayer = 1

    -- справжнє значення з'явиться, коли хтось переможе
    winningPlayer = 0

    -- 'start', 'serve', 'play' або 'done'
    gameState = 'start'

    Note

    winningPlayer = 0 — новий рядок. Гра працювала й без нього (змінна створювалася пізніше, коли хтось вигравав), але оголошення всіх змінних наперед робить програму зрозумілішою.

    Крок 5. Малюйте рахунок після повідомлень стану¶

    У love.draw():

    1. Видаліть рядки love.graphics.setFont(smallFont) і displayScore(), що стоять одразу після love.graphics.clear(...).
    2. Додайте displayScore() після всього блоку повідомлень if gameState == … і перед player1:render():
        -- рахунок малюємо перед м'ячем, щоб м'яч міг пролітати поверх тексту
    displayScore()

    player1:render()
    player2:render()
    ball:render()

    Note

    Те, що малюється пізніше, опиняється зверху. Тепер м'яч пролітає поверх великих цифр рахунку, а не під ними.

    Крок 6. Перенесіть displayFPS у кінець файлу¶

    Перенесіть displayFPS() нижче за displayScore() (порядок оголошення функцій не впливає на поведінку — так просто охайніше). У ній оригінальний репозиторій повертає колір так:

        love.graphics.setColor(255, 255, 255, 255)

    Note

    У LÖVE 11+ це те саме, що (1, 1, 1, 1) (значення понад 1 сприймаються як 1), тож підійде будь-який варіант.

    Крок 7. Покращте коментарі (необов'язково)¶

    Перепишіть коментарі над love.load, love.resize, love.update, love.keypressed і love.draw, щоб вони пояснювали, коли LÖVE викликає кожну з них — наприклад, що love.keypressed спрацьовує один раз на натискання, а love.keyboard.isDown — для утримуваних клавіш.

    Крок 8. Запустіть і перевірте¶

    Запустіть love .. Гра працює так само, як pong-12. Різниця — у коді: швидкість м'яча керується в одному місці, ініціалізацію логічно згруповано, а м'яч малюється поверх рахунку.
