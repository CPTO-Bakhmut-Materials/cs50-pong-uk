# Pong: від `pong-11` до `pong-12` — «The Resize Update»

## 1. Загальний опис завдання

Починаючи з `pong-1`, вікно має параметр `resizable = true`, але бібліотеці `push` ніхто не повідомляв, що розмір вікна змінився. Після зміни розміру зображення гри може мати неправильний розмір або положення.

У `pong-12` виправляємо це однією невеликою функцією: коли LÖVE повідомляє про зміну розміру, передаємо новий розмір у `push`, і та перераховує масштаб, щоб віртуальний екран 432×243 завжди правильно вписувався у вікно.

### Файли

| Файл | Що відбувається |
|---|---|
| `main.lua` | Змінюється — одна нова функція |
| [`sounds/*.wav`](assets/sounds/) | Готові ресурси, без змін. (Оригінальний репозиторій містить у `pong-12` трохи інші записи тих самих трьох файлів; у папці `assets` уже лежать саме ці фінальні версії, тож нічого робити не потрібно.) |
| `Ball.lua`, `Paddle.lua` | Без змін |
| [`class.lua`](assets/class.lua), [`push.lua`](assets/push.lua), [`font.ttf`](assets/font.ttf) | Сторонні, без змін |

## 2. Кроки від `pong-11` до `pong-12`

### Крок 1. Оновіть коментар-заголовок

```lua
    pong-12
    "The Resize Update"
```

### Крок 2. Обробіть зміну розміру вікна

Додайте нову функцію після `love.load()` (перед `love.update`):

```lua
function love.resize(w, h)
    push.resize(w, h)
end
```

> `love.resize(w, h)` — це **функція зворотного виклику** (callback) LÖVE, як `love.load` чи `love.keypressed`: LÖVE автоматично викликає її щоразу, коли змінюється розмір вікна, і передає нові ширину й висоту. Ми просто пересилаємо їх у `push`.

### Крок 3. Запустіть і перевірте

Запустіть `love .`. Потягніть за край вікна, щоб зробити його більшим, меншим, ширшим чи вищим (або розгорніть на весь екран). Гра залишається правильно масштабованою й відцентрованою, з чорними смугами, якщо форма вікна не відповідає 16:9.
